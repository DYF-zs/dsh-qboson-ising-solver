# 27 类组合优化问题：识别与建模配方

本页只讲**怎么把业务语义变成正确的 QUBO**，不涉及求解器调用。
约束写法见 [SKILL.md](../SKILL.md)；真机提交见 [流程补充](hardware-workflow.md)。

## 0. 用法

按**语义**选问题，不按用户用了哪个词。"分配""调度""覆盖""容量"在不同业务里对应不同模型，
很多用户根本不使用术语。用户说出问题名时，把它当作**待验证的假设**：抽取语义画像后与第 2 节核对，
不一致时以语义为准，并用一句话说明差异。

先写画像再选题。画像四个维度：

| 维度 | 要回答 |
|---|---|
| 决策 | 每个 0/1 变量表示什么 |
| 规则 | 硬性限制（"必须/恰好/不能"是硬约束；"尽量/最好"是目标或软约束） |
| 目标 | 收益最大 / 成本最小 / 只要可行 |
| 数据 | 图的边、集合、代理×任务矩阵、物品向量+资源矩阵、时长与截止期 |

## 1. 语义决策树

**A. 决策是「选不选」一批对象**（每个对象一个 0/1 变量）

| 规则的语义 | 目标 | 问题 |
|---|---|---|
| 某些对象两两不能同时选 | 收益最大 | `mwis` |
| 每条要求由两个候选之一满足 | 成本最小 | `binary_cover` |
| 候选是组合方案，每个元素最多被一个已选方案占用 | 收益最大 | `set_packing` |
| 同上，且方案是买家对一组商品的整包报价，同一买家最多中一标 | 收入最大 | `cap_pcf`（默认）/ `cap_svf` |
| 每个元素至少被一个已选方案满足 | 成本最小 | `set_cover` |
| 每个元素恰好被一个已选方案满足 | 成本最小 | `set_partition` |
| 同上 | 只要可行 | `exact_cover` |
| 单一资源用量不超上限 | 收益最大 | `knapsack` |
| 多种资源各自不超上限 | 收益最大 | `mkp` |
| 用户强调"带容量限制的选择" | 收益最大 | `capacity`（与 `mkp` 同模型） |
| 选中个数 ≤ k | 收益最大 | `cardinality_upper` |
| 选中个数 ≥ k | 成本最小 | `cardinality_lower` |
| 加权总量落在 [L, U] | 任意 | `interval` |
| 选 A 就必须选 B（B 可单独选） | 净收益最大 | `precedence` |
| A 与 B 必须同选同不选 | 任意 | `synchronization` |

**B. 决策是「把每个 X 分给一个 Y」**（变量 `x[Y][X]`）

| Y 的语义与规则 | 问题 |
|---|---|
| 每个 Y 最多接一个 X，无资源量 | `assignment` |
| 每个 Y 可接多个 X，受资源容量限制 | `gap` |
| Y 要先"开设"才可用，开设有固定费 | `facility_location` |
| Y 是颜色/类别，有冲突的 X 不能同类 | `coloring` |
| Y 只有两侧，要求两侧数值和（或个数、平方和）相等 | `partitioning` |
| 每个 X 放一个 Y，代价 = X 之间往来量 × 所放 Y 之间距离 | `qap` |

**C. 决策是「谁在什么时候做什么」**

| 语义 | 问题 |
|---|---|
| 人员 × 日期 × 班次，每班恰好一人，每人班数有上下限 | `scheduling`（护士排班模板） |
| 单机上的任务开始时刻，有截止期，按加权拖期计费 | `scheduling`（单机调度模板） |
| 作业由多道工序组成，每道工序指定机器，求最短完工 | `scheduling`（jobshop 模板） |

**路线与分区**：单条闭合路线访问全部城市一次 → `tsp`；同质车辆从单仓库出发、客户恰服务一次、每车有容量上限 → `cvrp`；
无向图分两侧、最大化跨区边权 → `max_cut`。

**D. 都不完全符合，但能写成 0/1 变量 + 线性/二次目标 + 线性/逻辑约束** → `linear_fallback` 通用建模。
目标与约束明确就继续，**不要因为库外问题、没有专用函数或问题名不确定而停下来提问**。

**E. 含整数、连续量或高阶乘积** → 先判断能否等价转换（有界整数的二元展开、可从约束严格推导的上界、
二元乘积的精确线性化），再按 D 建模。不得任意截断或取整。

## 2. 27 类速查

| ID | 名称 | 决策 / 规则 / 目标 | 约束原语 | 建模要点与易错点 |
|---|---|---|---|---|
| `mwis` | 最大权独立集 | 选对象 / 冲突对不能同选 / 收益最大 | `conflict` | 冲突边只罚一次（PCF 去重）；最大化用负权重 |
| `binary_cover` | 顶点覆盖 | 选对象 / 每对至少选一个 / 成本最小 | `or` | 罚项 `P(1-x_u)(1-x_v)`，不是 XOR 的平方 |
| `set_packing` | 集合打包 | 选方案 / 元素至多被占一次 / 收益最大 | `amo` | 每个元素一条 `le`；`amo` 用成对乘积，不用 slack |
| `cap_pcf` | 组合拍卖（PCF） | 选投标 / 商品与买家互斥 / 收入最大 | `amo` ×2 | 商品互斥 + 同一买家最多中一标两组冲突 |
| `cap_svf` | 组合拍卖（SVF） | 同上 | `le` + slack | 保留松弛变量形式，用于与 PCF 对照 |
| `set_cover` | 集合覆盖 | 选方案 / 元素至少覆盖一次 / 成本最小 | `ge` | 每个元素一条 `ge`；容量允许剩余，不能惩罚 `(load-C)²` |
| `set_partition` | 集合划分 | 选方案 / 元素恰好覆盖一次 / 成本最小 | `eq` | 每个元素一条 `eq` |
| `exact_cover` | 精确覆盖 | 选方案 / 元素恰好覆盖一次 / 只要可行 | `eq` | 目标为 0，`P` 可取下界 0 的情形 |
| `knapsack` | 0/1 背包 | 选对象 / 一种资源不超上限 / 收益最大 | `le` | 单行权重、单容量 |
| `mkp` | 多维背包 | 选对象 / 多种资源不超上限 / 收益最大 | `le` ×m | 每种资源一条 `le`，各自独立 slack |
| `capacity` | 容量约束选择 | 同 `mkp`，用户强调"容量"时用 | `le` | 与 `mkp` 同模型，只是命名不同 |
| `cardinality_upper` | 数量上限 | 选对象 / 个数 ≤ k / 收益最大 | 单位系数 `le` | 限制是**个数**还是重量/金额，要分清 |
| `cardinality_lower` | 数量下限 | 选对象 / 个数 ≥ k / 成本最小 | 单位系数 `ge` | 同上 |
| `interval` | 资源区间 | 选对象 / 加权总量 ∈ [L,U] / 任意 | `ge` + `le` | 两条都要有，不能只用一侧 |
| `precedence` | 选择依赖 | 选对象 / 选 A 必须选 B / 净收益最大 | `implies` | 罚项 `P·x_A(1-x_B)`；B 可单独选 |
| `synchronization` | 绑定选择 | 选对象 / 两两同选同不选 / 任意 | `equal` | 罚项 `P(x_A-x_B)²`，不是 `implies` |
| `assignment` | 一对一指派 | 分配 / 每任务一人且每人至多一任务 / 成本最小 | `eo` + `amo` | 任务侧 `eo`、代理侧 `amo`；带资源就不是它了 |
| `gap` | 广义指派 | 分配 / 每任务恰好一台，台内资源 ≤ 容量 / 成本最小 | `eo` + `le` | 容量是**上界不是等式**，允许剩余 |
| `facility_location` | 设施选址 | 开设 + 分配 / 每客户一个已开设施 / 成本最小 | `eo` + `implies` + `le` | 容量行含 `−C_i·y_i`，不能写成与开设无关 |
| `coloring` | 图着色 | 分到颜色 / 冲突对不同色，每对象恰一色 / 可行 | `eo` + `conflict` | 每顶点一条 `eo`，每条边×每颜色一条 `conflict` |
| `partitioning` | 数值划分 | 分到两侧 / 两侧和相等 / 可行 | `eq` | 残差 `Σ v_i(2x_i-1) = 0` |
| `scheduling` | 排班 / 单机调度 / jobshop | 人员×日期×班次 / 每班恰一人、班数区间 / 可行 | `eo`+`amo`+`conflict` | jobshop 用时间索引，**不用 big-M** |
| `tsp` | 旅行商 | 城市访问次序 / 城市与位置恰一 / 闭合路线费用最小 | `eo` ×2 | 位置编码 `visit_{city}_{position}`，两组 `eo` |
| `cvrp` | 容量车辆路径 | 车辆访问次序 / 客户唯一、容量、仓库后缀 / 总费用最小 | `eo` + `conflict` + `le` | 见第 4 节 slot 布局 |
| `max_cut` | 最大割 | 二元分区 / 基础无硬约束 / 跨区边权最大 | — | 无硬约束时 `P=0`；固定一个顶点破对称 |
| `qap` | 二次指派（布局） | 对象放位置 / 对象恰一位置、位置至多一对象 / 往来量×距离最小 | `eo` ×2 | 二次项 `f[i][j]·d[k][l]`，对称时只计一次 |
| `linear_fallback` | 通用 0/1 模型 | 不属于以上任一类但能列出 0/1 决策与规则 | 任意 | 直接列变量、目标、约束行 |

## 3. 约束原语与无辅助变量的精确罚项

优先使用**不需要辅助变量**的精确形式；只有识别不出特殊结构的一般线性不等式才用松弛变量法（SVF）。

| 原语 | 约束 | 罚项 | 辅助变量 |
|---|---|---|---|
| `conflict` | x + y ≤ 1 | `P·xy` | 无 |
| `amo` | Σx ≤ 1 | `P·Σ_{i<j} x_i x_j` | 无 |
| `or` | x + y ≥ 1 | `P(1-x)(1-y)` | 无 |
| `eo` | Σx = 1 | `P(Σx − 1)²` | 无 |
| `implies` | x ≤ y | `P·x(1-y)` | 无 |
| `equal` | x = y | `P(x − y)²` | 无 |
| `eq` | 其他线性等式 | `P·(整数化残差)²` | 无 |
| `le` / `ge` | 其他线性上/下限 | 加有界二进制 slack 后 `P·(残差)²` | ⌈log₂(范围+1)⌉ 位 |

要点：

- **冲突去重（PCF）**：所有 `conflict`/`amo` 行展开成冲突边集，**每对变量只罚一次 `P·x_k·x_l`**。
  同一对出现在多行时不重复累加，系数范围更小，int8 精度更好。
- **冗余行**：在 0/1 下恒成立的行不加罚项也不加 slack；没有任何 0/1 取值能满足的行是输入错误，直接报错。
- **slack 位权**：`[1,2,4,...,r]` 精确覆盖 `[0, 范围]` 内每个整数且不越界。
  容量允许剩余时不能直接惩罚 `(load − C)²`，那会强迫用满。
- 取负后的形式也要能识别：`−x−y ≤ −1` 就是 `x+y ≥ 1`；`x_u − x_w ≥ 0` 就是"选 x_w 必须选 x_u"。

## 4. 题型级配方

**CVRP**：`slots` = 单车容量内最多可装客户数（按需求贪心累加），车辆数 `k = min(n_vehicles, |customers|)`；
变量 `route_{vehicle}_{slot}_{node}`，depot 符号填充未用后缀，`closed_route` 冲突约束禁止内部 depot 访问（防一车多趟）。
若最大可能装载都不超过容量，就不要引入冗余 slack 位。

**设施选址消去**：`eliminate_last=True` 时做**精确变量消去** `serve[last,j] = 1 − Σ_{i<last} serve[i,j]`。
AMO 保证代入式仍为二值、不丢解。附加"恰开 k 家""固定关闭末设施"等规则会破坏"末设施免费固定开"的假设，
增加这类规则时优先关闭消元。

**jobshop**：时间索引非抢占 + unary makespan 选择，**不用 big-M**。
`eo`（每工序一次）+ `eo`（makespan）+ `amo`（机器时刻）+ `conflict`（先后序/超 makespan）。

**assignment → GAP**：无资源时代理侧是 `amo`（至多一任务）；有资源时代理侧改成 `le`（资源 ≤ 容量），
这就是广义指派。别把带资源的题还当一对一指派建模。

**set_system 三态**：同一套变量结构切 `cover` → `ge` 行、`pack` → `amo`（或强制 SVF）、`partition` → `eq` 行。

**TSP/CVRP 距离**：坐标给的是"业务请求"，距离矩阵和取整由代码算。
取整用精确半进位 `⌊√S + 1/2⌋`（整数不等式判定，全程无浮点），不要先转 float 再 round。

## 5. 罚参数

第一优先级是**QUBO 与原问题等价**：QUBO 的每个全局最优解都是原问题的最优可行解。
在此前提下优先用**较小的已证明充分罚参数**，控制系数范围。

默认策略 `repair`，按约束结构自动判断：

1. 没有有效硬约束 → `B = P = 0`（例如基础 Max-Cut）。
2. 结构与某个已证明情形吻合 → 用该结构的充分阈值 B；适用多个界时取已验证的较小值。
3. 否则 → 通用宽松界 `B = Σ|c_k|`（目标线性+二次系数绝对值之和）。

未指定罚系数且有有效硬约束时，可取 **P = B + 1**；任务已指定 P 时以任务为准。

| 依据标签 | 适用结构 | B |
|---|---|---|
| `monotone_packing_delete_repair_pmax` | 只有 `le`/`amo`/`conflict`，系数非负，收益非负 | 最大单项收益 |
| `monotone_covering_add_repair_cmax` | 只有 `ge`/`or`，系数非负，成本非负 | 最大单项成本 |
| `complete_assignment_delete_and_fill_maxcoefficient_family_tight` | `eo` 与 `amo` 组成完整指派网格，费用同号 | 最大 \|费用\| |
| `uncapacitated_facility_open_and_fill_repair` | 无容量设施选址 | 开设费与最便宜服务组合的最大值 |
| `linking_component_constant_repair` | 只有 `implies`/`equal` | 各连通分量修复代价最大值 |
| `isolated_exactly_one_exact_sorted_prefix_threshold` | 只有一条恰一约束 | 排序前缀阈值 |
| `isolated_cardinality_upper_exact_order_statistic` | 只有一条单位系数上限 | 第 k+1 个收益 |
| `isolated_cardinality_lower_exact_order_statistic` | 只有一条单位系数下限 | 第 k 个成本 |
| `permutation_nonnegative_gap2_sufficient` | 完整方形排列的两组 `eo`，最小化非负目标 | U/2 |
| `onehot_block_nonnegative_sufficient` | 互不相交的 `eo` 组覆盖变量，最小化非负目标 | 恰一块上界 U |
| `feasibility_zero_objective_bound_if_feasible` | 目标为 0（只求可行） | 0 |
| `unconstrained_no_penalty_required` | 没有有效约束 | 0 |
| `paper2_general_l1_bound` | 无更小适用结构界 | Σ\|c_k\| |

通用下界的依据：每条约束先整数化并约去公因子，任何违规至少产生 1 个单位的平方残差，
所以不可行解能量至少增加 P；任意两解的目标差不超过 Σ|c_k|。因此 `P > Σ|c_k|` 对任意约束组合都保证等价。

结构修复界通常是**充分界**，不能一律称为实例最小阈值；某一问题族存在达到该界的实例，
也不表示该族每个实例都达到。

## 6. 易混淆对照

只在目标函数或约束无法唯一确定时追问，集中问最少的业务信息。下面的问题只用于消除实际歧义，
不是逐项必问清单；不询问模板选择或"是否继续"。

| 容易混淆 | 区分性问题 |
|---|---|
| `assignment` / `gap` | 每个人（机器）能接几项？限制的是项数，还是工时、资源用量？ |
| `set_cover` / `set_partition` / `set_packing` | 一个需求可以被多个方案同时满足吗？每个需求都必须满足吗？ |
| `precedence` / 时间调度 | "A 在 B 之前"是指选了 A 就得选 B，还是 A 做完 B 才能开始？ |
| `knapsack` / `cardinality_upper` | 限制的是个数，还是重量、金额？ |
| `knapsack` / `mkp` | 受限的资源有几种？ |
| `mwis` / `set_packing` / `cap_*` | 冲突来自共用资源、两两不兼容，还是同一买家的多个报价？ |
| `partitioning` / `set_partition` | 是把每个数分到两侧，还是从候选方案中选出覆盖所有元素的组合？ |
| `facility_location` / `gap` | 服务方需要先决定开不开、开设有固定费用吗？ |
| `precedence` / `synchronization` | B 能不能单独被选？ |
| `coloring` / `scheduling` | 是只分到几个互斥类别，还是有具体时长和开始时刻？ |

目标方向、必要系数、容量、预算、时域或硬约束语义缺失且不能从材料确定时才追问。
单位只在影响系数解释或约束比较时需要澄清；编号起点可由标签和数据关系唯一确定时直接转换并记录。

## 7. 识别完成后记录

- `problem_type`（以及模板，若与问题 ID 不同，如 jobshop）；
- 语义画像；
- 变体差异清单及每条的处理方式；
- 实体名称到 0 起始编号的映射（交付时翻译回业务名称用）。

变体 = 基础问题 + 差异。先用语义核心确定基础问题，再把多出来或改变的每条规则列为差异：
能直接改参数就改参数；需要换模型就换；需要追加约束就做通用改写；需要新变量就先定义新变量、上界和解码映射。
例："任务分给几台机器，每台工时有上限，而且任务 3 不能给机器 2" → 基础是 `gap`，
差异是一条禁配，处理为固定 `assign_2_3 = 0`（用硬禁配，不用"大成本"代替）。
